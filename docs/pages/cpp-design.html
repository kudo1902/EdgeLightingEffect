01 Scope and principles

The library is an OpenGL renderer for a glowing rounded-rectangle outline and a few companion layers. Its C++ side does three jobs: it holds the state a host authors, it turns that state into GPU work as cheaply as each frame allows, and it keeps the GL context exactly as the host handed it over.

This page describes the code as of the add_shared_buffer_architecture branch on 2026-10-20. Where it and a header under lib/include/ disagree, the header wins. For the shading itself - what each program computes and why - read the mechanism reference and the shader outputs page; for the GPU vocabulary, the onboarding guide; for the short version of this page, implementation.md.

The design principles, in one place

Every section below is one of these applied to a particular piece. They are not aspirations; each one is in the code because breaking it was measured or caused a defect.

  • The orchestrator owns state; plug-ins own drawing. EdgeLightingEffect holds the configuration, the clock and the animations and draws nothing. Each visual layer is a BaseRenderer that draws one thing and knows nothing of the others.
  • Configuration is a value, compared whole. A Config is plain data with operator== on every struct. The effect notifies renderers only when the composite actually changed, and renderers rebuild only what the changed fields feed.
  • Skip by key, not by guess. A pass runs only when something it reads moved, and "what it reads" is taken from what the pass binds - version numbers on the GL objects - wherever a hand-written field list could fall out of step with a shader.
  • Build late, release early. A program is compiled on the first frame that draws with it; a buffer is allocated on the first frame that writes it and given back when the layer is off or the buffer goes unread. A host that never uses a feature never pays for it.
  • Leave the host's GL state as found. Every pass that retargets restores the framebuffer and viewport it was handed - never framebuffer 0 - and every layer leaves one known blend state. What the library does not set, the host supplies.
  • Offscreen first, then one run on the target. A frame is two phases across all layers, so a tile-based GPU draws the caller's framebuffer in one unbroken run, and a layer that reads another's image sees this frame's.

02 Layers and modules

Dependencies point down only. A host talks to EdgeLightingEffect, directly in C++ or through the C ABI; the effect talks to its renderers only through BaseRenderer's virtuals; renderers build everything from the GL wrappers and the generated shader sources. The one place the effect names concrete renderers is its factory, CreateRenderer, which is why edge-lighting.cpp includes all five headers and edge-lighting.h includes none.

Three consequences of that shape are worth stating, because the code relies on them:

  • Config is the only type every layer shares. Each renderer reads its own sub-config plus geometry; the exceptions are deliberate and few - the droplets read neon.glowSide for the band's side, the debug layer reads neon to describe it, the neon reads debug.opaqueOnly because it selects which of its passes run, and the spotlight reads nothing but spotlight.
  • A renderer can be driven without the effect. Nothing in a renderer calls back into the effect; a host (or a tool such as neon-scale-check) can construct one, call its four methods and get the same frame. The renderers with an offscreen phase detect a missing RenderOffscreen and run it themselves (section 5).
  • The C ABI is a client, not a layer underneath. libedge-lighting-c wraps EdgeLightingEffect exactly as a C++ host would; there is no second implementation of anything. demo-capi/ cannot see lib/include/, which proves the ABI is enough for a real UI.

04 One frame through the effect

A host makes two calls per frame - Update(dt), then Render(w, h) - and optionally SetConfig before them. Figure 3 is what the effect does with them.

The composite, and why it allocates nothing refreshActiveConfig

With no animation attached, the active config is the base: it is copied only when they differ. With animations, the composite is built in mScratchConfig - copy-assigned from the base, which reuses the vector capacity already there - then every animation's Apply writes its overlay, the result is compared with the active config, and on a difference the two are swapped. The swap hands the scratch the buffers the old active config owned, already the right size for the next frame. A local copy-construct allocated 3 blocks a frame on the default config and 19 at the segment and arc caps; this path allocates none. That was not a throughput problem (about a microsecond) but a fragmentation and jitter one on the embedded targets the library ships to.

Notification is conditional, and may come twice SetConfig

SetConfig returns at once when the new base equals the old; otherwise it stores it and runs the same refreshActiveConfig. Two things follow, and every renderer is written for both:

  • OnConfigChanged is not a per-frame callback. An idle effect never fires it; a running animation fires it nearly every frame. A renderer can treat each call as a real change but must still gate its own rebuilds on what changed.
  • It can run more than once between two frames - a host's SetConfig, then Update with an animation running - and before Initialize (AddRenderer hands a renderer the current config at once). So the neon accumulates what moved (its dirty masks and mIntensityMoving are OR-ed, never assigned) and defers GL rebuilds until mInitialized.

Render runs in two phases EdgeLightingEffect::Render

Every layer's RenderOffscreen runs before any layer's Render. Two reasons, both load-bearing. On a tile-based GPU, every switch away from the caller's target and back stores its tiles out and reloads them; with all offscreen work first, the target is drawn in one unbroken run per frame. And a layer that reads another layer's shared buffer sees this frame's image wherever the two sit in the order (section 12). The order between layers decides only compositing - what lands on top - and SetRendererOrder can change it without re-initialising anything.

Registration and initialisation

  • Initialize() logs the driver's extensions and caps, initialises every registered renderer, and drops any that fail - the rest of the effect still runs. Call it once.
  • AddRenderer(ptr) hands the renderer the registry first (so Initialize can claim a slot), initialises it on the spot if the effect is already initialised (a late renderer is not left drawing with program 0; one that fails is not added), and then calls its OnConfigChanged with the current active config so its first frame is not blank.

Layers as bits RendererLayer

Each layer is one bit - NEON 1, DROPLETS 2, LENS_FLARE 4, SPOTLIGHT 8, DEBUG 1<<30, CUSTOM 0 - numbered exactly as the C ABI's el_renderer_flags_e, with static_asserts in capi-internal.h holding the two together. DEBUG sits on bit 30 so that a content layer added later takes the next free low bit and never renumbers it. The effect builds and reorders its stack by layer:

  • CreateRenderer(layer) and GetDefaultLayerOrder() (neon, droplets, flare, spotlight, debug) are the only places that list the layers; IsValidLayerList reads "known" from the second, so a new layer is added in those two functions and nowhere else in the core.
  • AddRenderer(layer) refuses a second renderer for a named layer, so the layer calls can always tell which one to move.
  • SetLayerOrder refills the named layers' slots in the new order and leaves CUSTOM renderers where they are; SetRendererOrder underneath accepts any permutation of the registered pointers and refuses everything else, so neither can add or drop a layer.

The frame-state pattern

The three renderers with an offscreen phase (neon, flare, spotlight) keep a small FrameState: RenderOffscreen resets it, sets prepared and the viewport, and leaves what Render needs (whether the scaled buffer is ready; for the neon, the UV maps and the ring's decision). Render consumes it, and runs RenderOffscreen itself when no call for this viewport came first - which EdgeLightingEffect never does, but a host driving one renderer directly might.

Adding a renderer

  1. Subclass BaseRenderer; implement the five pure virtuals, and RenderOffscreen if it draws offscreen at all.
  2. Add a sub-config to Config, with operator== over every field, and add it to Config::operator==.
  3. Add a RendererLayer bit, a case in CreateRenderer, an entry in GetDefaultLayerOrder; mirror the bit in el_renderer_flags_e with its static_assert.
  4. Register it in demo/src/main.cpp and give it a section in DebugUI (and in demo-capi/, through C ABI setters, if it is exposed there).

06 Configuration and change detection

Config (lib/include/core/config.h) is six sub-structs - geometry, neon, debug, droplets, lensFlare, spotlight - each a plain value with operator== and operator!= covering every field, down through the nested types (Cutoff, ColorStop, SegmentBoost, Arc, SpotLight, ClipArea, ...). Two mechanisms rest on those operators: the effect's decision to notify at all, and every renderer's decision about what to rebuild. A field missing from its operator== breaks both silently - the most common way to introduce a bug here, and nothing but review catches it.

Inside the renderers, three styles of gate decide what work a change causes. They trade differently between precision and the risk of going stale, and the code chooses deliberately between them:

StyleComparesExamplesHow it fails
Field-list gate, in OnConfigChangednamed fields, old against newthe neon's samplesDirty, geometryDirty, fillDirty, glowCoverShapeDirty; the droplets' geometry and band extent; the flare's three ghost fields; the spotlight's whole sub-configA field that feeds the rebuild but is missing from the list leaves the previous config's result in place. Two real cases: glowSide and insideCutoff once bounded the glow quad without being in its gate; the light blocks were gated on the arcs and segments and missed the perimeter (V28).
Self-guarding wrapperits own inputs, or the bytes it would uploadGradientRingLUT::Bake (stops, blend space, size), SpanAtlasLUT::Bake (each row's stops and space), UniformBuffer::SetData (memcmp with the last upload), ShaderProgram::SetUniform (last value per location)It cannot go stale; its cost is the compare. Call sites call it unconditionally - bakeLUTs runs on every config change, and the light blocks are packed on every frame.

The preferred direction has been, over the branch's history, away from field lists and toward the other two. The emission pre-pass used to re-bake on "any config change" (mEmissionDirty); it now keys on what it binds, so an intensity or geometry animation never re-bakes it and nothing that does move it can be missed. Field lists remain where the inputs are visible in the same place as the gate (the flare's ghosts) or where the alternative would be comparing large state each frame (the neon's geometry gates, each commented with the fields it reads and why).

Wide where it must be, narrow where it pays The neon clears its offscreen reuse (mOffscreen.reusable) on any change to config.neon or config.geometry - deliberately wide, since pass 1b reads most of the neon's config. But not on another layer's change: the call comes for any change to the composite, and an animation of the flare's sun changes it every frame. Gated on "anything", the neon drew pass 1 directly every frame - 4.9x with the hue rotating and 15x still at scale 1.0 on the AMD 5300M (I47).

07 Time and phases

An effect may run for days. Clock (animation/clock.h) keeps its time in double; its Update(dt) adds dt while playing and returns it, or returns 0 while paused. Every renderer's time parameter is that double. A float accumulator stepped 10 s of 60 fps frames by 9.375 s after half a day and froze past 219 s (about 6.07 days).

No shader is handed an absolute time. Each renderer reduces it on the CPU, in double, to the bounded phase its shader reads, and each phase driven by a config rate is a PhaseAccumulator: the rate integrated over clock time, re-anchored whenever the rate changes, wrapped to its period. Not time * rate, whose slope under a moving rate is rate + time * d(rate)/dt - a minute into the clock the HueRotationEaseReverse preset moved the hue 0.44 turn a frame against the 0.013 its rate allows. While a rate holds, the accumulator returns exactly GetCyclePhase / WrapPeriod, so a constant rate renders as it always did; a rate set to 0 holds the phase where it stopped.

Each accumulator is advanced in the renderer's Update every frame - even while the layer is off, so a rate that moved meanwhile is integrated as it moved - and read again in its draw for the same time, which moves nothing. A new time-driven term in a shader gets a phase the same way. neon-scale-check clock is the gate: frames of every time-reading layer started at about 10 days must match the same frames started at 0.

08 Animation

Animations never touch a renderer. They write into a Config - the effect's scratch composite - and the renderers see the result like any other change. Three layers, low to high:

LayerFileDesign
Modulatoranimation/modulator.hHeader-only pure functions of time: Constant, Oscillator (sine, triangle, square, sawtooth), Ease, Sequence, Multiplier, Adder, Remap. Composable, stateless, no coupling to Config; Evaluate takes a double.

AnimationManageranimation/animation-manager.hThe attach list. Update ticks each animation; Apply layers them onto the composite in attach order, so a later animation of the same field wins.

Two implementation details make the run loop robust to its own callbacks. OnComplete and OnStateChanged fire from inside Update, and a callback may attach, detach or even re-enter: so AnimationManager::Update (and AnimationGroup::Update) walks a snapshot of the list, skips anything detached earlier in the walk, defers anything attached during it to the next frame, and ignores a re-entrant Update - with a scope guard that resets the walk even if a callback throws. And each callback is copied before it is invoked, so a callback that replaces itself does not destroy the function it is running in. There is no "revert to base" end action: Detach gives that, since the next composite simply no longer contains the overlay.

09 NeonRenderer: anatomy

The neon is most of the library: one header of about 1900 lines, one source of about 5000, eleven programs and seven offscreen buffers. It stays navigable because both files are laid out by role, in the same order.

The header's private section runs: types, programs (the ensure* builders), buffers (ensureGlowCoverBuffer), CPU-side inputs (rebuildLoopSamples, bakeLUTs, packLightBlocks), geometry (setup*Geometry), skip keys (getEmissionInputs, isEmissionTableStale, getGatherInputs), uniform uploads, then the passes in the order the frame runs them. The members follow the same roles, then one group per offscreen buffer. The .cpp defines the methods in the header's order, and above them, in an anonymous namespace, about sixty free helpers - each a pure function of the config and a few numbers (GetGatherScale, GetBufferRegion, GetGlowInnerReach, IsFieldEligible, IsGlowCoverUnread, PackArcFlags, ...), which keeps the class's own methods to scheduling and GL.

10 NeonRenderer: the frame

RenderOffscreen is a pass schedule and nothing else: it decides, then calls one method per pass. Every decision is made before the first draw, so the target is captured only on a frame that actually leaves it. In order:

  1. Reset mFrame. Layer off: MarkNotReady and return.
  2. Consume mIntensityMoving (set by OnConfigChanged); read the hue phase for this time.
  3. debug.opaqueOnly: MarkNotReady and return - Render draws the fill alone, and no glow program is compiled.
  4. glowReady = the four glow programs build, and either the coverage table is unread (a uniformly lit ring) or its program, fill program and buffer are ready.
  5. packLightBlocks: pack both light blocks (an unchanged pack uploads nothing) and bind their bases. First, because the emission key reads their upload counts.
  6. emissionStale = isEmissionTableStale(huePhase); glowCoverStale = a dirty piece and the table is read.
  7. reuseOffscreen = mOffscreen.reusable, neither table stale, same viewport.
  8. Regions: the reduced buffer is the viewport; the glow quad's window of it is both the field's region and what BeginWrite clears.
  9. The glow field's decision: eligible, worth its memory (FIELD_MIN_FILL), programs built, not a reuse frame - then mGlowField.schedule.Decide(...). The ring field's likewise, recording its layout on a bake frame.
  10. Capture the target if anything will draw offscreen. Run P0, P0b, P1a (unless reused or its cache answers), P1f then P1c or P1b, P1r. Restore the target.
  11. mOffscreen.reusable = glowReady && !field.use; MarkReady or MarkNotReady; fill mFrame; leave blending on with GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA.

Render then draws on the caller's framebuffer, premultiplied over: P2a the fill (under the glow), then - if the offscreen phase succeeded - P2b the blit and P2c or P2r the edge ring, through one full-resolution matrix built once and handed to both. The blit and the ring tile the frame exactly only if their shared edges land on bit-identical positions: the same vertex floats (setupRingGeometry emits both from one set), the same vertex stage (invariant gl_Position in neon.vert), and the same uMVP. neon-scale-check partition tests the result across a thousand random configs.

11 Skip keys and caches

Most frames a host draws change little or nothing, and most of the neon's cost is in passes whose output persists between frames. So the implementation's central technique is to record what each persistent buffer was drawn from, and skip the pass while that still holds. Eight mechanisms do it. The first five are exact - a frame drawn with them is byte-identical to one without - and the last three are approximations measured to stay within a level or two.

Keys made of version numbers

The two keys at the bottom of the pipeline compare versions, not contents and not config fields. UniformBuffer::GetUploadCount moves only on an upload whose bytes changed; BaseLUT::GetUploadCount moves on every upload, a cross-fade frame's included; EmissionBake::version moves on every bake of the table. So the gather's key holds the table's version, and a fresh table re-runs the gather without anyone comparing texels. The hue phase is the emission table's only time input - it reaches the shader once, as si - uHuePhase - so at a hue rate of 0 time never re-bakes it. The rule that keeps all of this honest is written at each key: add an input to the pass and it belongs in the key - a field, a term in operator==, a line in get*Inputs.

The field schedule LazyBake

A field is a bake reused across frames, so baking one on a frame whose config changes again next frame is pure loss - a bake and a composite on every frame measured 5-7% slower than shading directly. LazyBake therefore bakes only a config that has held for a frame, with two exceptions: the very first frame a config the field can serve is drawn (to warm every program's first draw at once), and the intensity, which a field baked at intensity I0 can serve scaled by I / I0 while the intensity moves below I0.

Verifying a skip NeonBypass

Every skip is a correctness risk - a key missing an input draws a stale frame - so every skip has a bypass bit. NeonRenderer::SetBypass(mask) is a verification hook with no config field and no C ABI mirror: with NeonBypass::ALL the renderer redoes everything it would otherwise keep. neon-scale-check sequence drives seeded random config sequences through three renderers side by side - all bypassed, only the exact skips active (must be byte-identical, frame and shared buffer), and as shipped (within 2 levels, 6 where the intensity moved) - and --isolate names the skip behind a failure. A new skip gets a bit, or the tool cannot see it.

12 Shared buffers

Layers composite by blending, and that is all most of them see of each other. A layer that already draws an offscreen image can also share it: no pass is added, nothing is copied, and the reader samples the producer's own buffer.

Three types, split across two headers on purpose:

  • SharedBufferId - one value per shared image; NEON today, then COUNT.
  • SharedBufferRegistry (core/shared-buffer-registry.h) - a directory: one slot per id, holding its producer's buffer. It allocates, draws and schedules nothing. Register lets one producer claim a slot (a second is refused and logged), Unregister gives it back if the caller is the holder, Find hands a reader a shared_ptr<const SharedBuffer>. This header only declares SharedBuffer: it reaches every host through base-renderer.h and edge-lighting.h, and the full type would drag in the GL loader, which collides with a host's own GL headers.
  • SharedBuffer (core/shared-buffer.h) - the GL buffer and the state that says what it holds: format tier, last write window, viewport, version, ready. Producers and readers include it themselves.

The contract a reader relies on

  • It covers the whole viewport it was drawn for (GetViewport()), so a fragment of a pass at that viewport finds its own pixel at uv = gl_FragCoord.xy / viewport. Colour attachment 0, GL_LINEAR, clamped to edge.
  • IsReady() holds this frame's image from the end of the producer's RenderOffscreen; GetVersion() moves whenever the producer redraws it, so an unchanged version means unchanged texels - a reader may cache against it.
  • The handle is read-only by type. The write side - BeginWrite, MarkReady, MarkNotReady, Release - is the producer's alone.
  • For NEON: the filament, halo and bloom at NeonConfig::resolutionScale, premultiplied, tone-mapped and undithered, RGBA16F (RGBA8 fallback). No opaque fill, and not the one-sided cut or the cutoffs, which the blit applies at full resolution; a reader that wants them multiplies them in from the config, as neon-blit.frag does. Not ready while the layer is off, in opaqueOnly, or after a failed pass.
// A reader: any renderer's Render (phase 2), wherever it sits in the order.
#include "core/shared-buffer.h"

std::shared_ptr<const SharedBuffer> neon;
if (GetSharedBufferRegistry())
{
    neon = GetSharedBufferRegistry()->Find(SharedBufferId::NEON);
}
if (neon && neon->IsReady())
{
    mShader.Use();
    neon->BindTexture(6);
    mShader.SetUniform("uNeon", 6);
    mShader.SetUniform("uNeonViewport", glm::vec2(neon->GetViewport()));
    // GLSL: vec2 uv = gl_FragCoord.xy / uNeonViewport;
}

The write side SharedBuffer::BeginWrite

BeginWrite(texels, window) sizes the buffer in the best format left - walking the producer's list from the best one the driver has not refused, the tier only ever advancing - binds it, and clears only what can hold anything but 0: the union of this write's window and the last write's, or the whole buffer when its texels are undefined (fresh, reallocated, released). Clearing the whole viewport-sized buffer on every hue or intensity frame cost a small rect up to 1.65x at 4K on the AMD 5300M. It refuses to bind when no format allocates, because binding a failed Framebuffer binds id 0 - the caller's framebuffer - and the clear would erase it. The caller lifts the host's scissor first (NoScissorScope), since a box in window pixels lands on the wrong texels of a reduced buffer.

Adding a producer

  1. Add a SharedBufferId value before COUNT.
  2. Own a std::shared_ptr<SharedBuffer> with its format list; Register it in Initialize and remember whether the registry accepted it.
  3. In RenderOffscreen: BeginWrite, draw, MarkReady(viewport) - or MarkNotReady() on a frame with nothing to share. Keep the version on a frame that reuses the image.
  4. Release() when the layer is disabled (from OnConfigChanged); in the destructor, Unregister then Release, while the context is still current.

neon-scale-check shared-buffer is the gate for the neon's: probe renderers before and after the neon must be handed the same ready buffer on every scene and scale, still frames must not move its version, and the buffer's light on the line must not fall short of the frame's.

The failure model

  • Formats fall back, once. The buffers that want half float (the emission table, the coverage tables, the gather buffer, the reduced buffer) carry a list, best first, walked by ResizeInBestFormat or SharedBuffer::BeginWrite from a tier kept beside the buffer - a released buffer cannot remember a refusal itself. A fallback is logged once, with what it costs - for the emission table, that arc intensities and stacked segment boosts above 1.0 will clamp. The fields have no 8-bit fallback: a driver that cannot render half float shades directly (LazyBake::unavailable).
  • Programs fail once. Recorded, logged with what the frame loses, never retried.
  • A frame degrades, it does not break. A failed glow pass skips the composites that would read its buffer, so the frame shows the fill alone rather than a stale image; Initialize fails only if the emission program or table cannot be built, and then the effect drops the layer and runs the rest.

15 The C ABI

libedge-lighting-c (lib/capi/) is a flat extern "C" surface over the C++ library for P-Invoke, ctypes and cgo. edge-lighting-capi.h is the single public include. Its design is a thin, strict adapter:

ConcernHow it is handled
HandlesThree opaque families - effect, animation, modulator - defined in capi-internal.h. An effect handle is { Config config; unique_ptr<EdgeLightingEffect> impl; }; the other two wrap an AnimationPtr / ModulatorPtr, so attaching an animation shares it rather than transferring it.

16 Shaders as build products

There is no runtime shader I/O. lib/CMakeLists.txt reads every lib/shaders/*.{vert,frag} and substitutes it into shaders.h.in through configure_file(), producing build/lib/generated/shaders.h: each source a const char* const raw string in EdgeLighting::ShaderSource. The C++ side sees a shader as a string constant and nothing more.

  • Constants shared by both languages live in the four tuning headers (neon-, droplets-, lens-flare-, spotlight-tuning.h), written with #define - the only form valid in C++ and GLSL ES 3.00 - and injected verbatim, so a shader constant and its CPU mirror cannot drift.
  • GLSL shared by several programs lives in .glsl chunks (neon-common, neon-pieces, neon-sdf, neon-grade, spotlight-dither) injected the same way, since GLSL has no #include.
  • Variants are sources of their own over a shared chunk (the field bake is neon-field-bake.frag over neon-shade.glsl, calling neonShade with a constant argument), not a runtime branch in a hot program.
  • Per-index data goes in a layout(std140) uniform block uploaded through UniformBuffer, never a bare uniform array - the form is unavailable on the restricted targets the library ships to and compiles fine on desktop GL, so testing would not catch it.
  • Adding a shader touches three places: both lists in lib/CMakeLists.txt (CMAKE_CONFIGURE_DEPENDS and file(READ ...)) and shaders.h.in.
